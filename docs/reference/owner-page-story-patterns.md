## 核心：每个元素都是讲故事的人

Owner 十几轮评论反复说的是同一件事：**页面不是把内容排整齐，而是讲一个故事。** 落到每一层：

| 层 | 要回答的问题 | 合格的样子 | 不合格的样子 |
| --- | --- | --- | --- |
| 整页 | 只读标题和记忆句，能不能连成一个故事 | 预测表 §0 → §10：怎么执行 → 预计赚多少 → 为什么能赚 → 防守放哪 → 代价 → 定了什么 → 接下来 | 条款按编号堆叠，标题是“候选池”“对照”这类名词 |
| 一节 | 这一节的结论是什么、几秒内从哪看到 | 记忆句带数字 → 一个证据视觉（图、步骤表、计分条）→ 明细折叠 → 读法 ≤ 3 条 | 记忆句之后连着三四张表，没有图、没有读法 |
| 一个元素 | 看这里先看什么、为什么、和前后怎么接 | 步骤表：大字步骤名 + 蓝字“决定什么” + 标签化的看/判/得 + 例子“输入 → 结果” | 有边框、有加粗、但全是段落（“加粗 + 纯文本不合格”） |
| 一个格子 | 这一格是不是决定结论的那一格 | 整张表只框一两格；数字按方向上色 | 整列上色、长句塞满格子 |

**判断标准只有一个：Owner 不读正文，只看视觉重点，能不能讲出这一节的结论。** 讲不出来，就还没做完——不管 lint 有没有报错。

## 一节的标准骨架（预测表每节都是这个顺序）

1. `## 问题：结论`，结论里有方向和数字。
2. `> **记忆句**`：一句话，带决定结论的一两个数字。
3. **证据视觉**（必须有一个，按内容选，见下一节）。
4. `<details>` 明细表：带“结论 / 判 / 状态”列，短标签。
5. 读法：`- **加粗短语**：解释`，最多 3 条；第一条通常是“读这张图”。

预测表 11 节里 9 节有证据视觉；预注册初稿第 2 版 10 节里 0 节有（2026-11-23 自查）。

## 模式清单：组件、md 写法、通用还是专用

| 模式 | 解决什么 | md 写法（生成器靠它触发） | 生成器 | 适用 |
| --- | --- | --- | --- | --- |
| 结论图 | 一节最重要的证据先给图 | `![图的标题就是结论](../assets/...png)`，脚本在 `scripts/preflight/charts_*.py` | figure | 通用 |
| 步骤表 | “每一步干嘛”一眼看出 | `1. **步骤名**：**决定什么**。看：a · b｜规则：c · **d**｜结果：e。例（月份）：输入 → 结果。` | `flow_steps` + `spec_grid` | 通用：任何 3–5 步流程 |
| 算式表 | “核心数字怎么算出来的” | `**X 怎么算**：记下：… → 算 t：… → 换成 p：…`，紧跟表头带 ①②③ 的表 | `calc_grid` | 通用：三步以内的计算链 |
| 计分条 | 一组检验/判据过了几个 | 表里有“结论 / 判”列，值是短标签（通过、成立、待定、不采用） | `polish.score` | 通用 |
| 对基准上色 | 每个数字好还是差 | 表里有“基准”列；回撤、波动、成本类自动按越低越好 | `table_focus` | 通用 |
| 列角色 | 表头决定列的读法 | 表头写“结论 / 为什么 / 代价 / 超出就要查 / 状态 / 旧 | 新” | `table_focus` | 通用 |
| 行内条 | 同列数字比大小 | 数字列 + 同量纲 | `.ib` | 通用 |
| 页首结论 | 现在怎样、要我做什么 | 三格表：进度 / 结论 / 需要你；“不用操作”显示绿色 ✓ | `status_hero` / `generic_hero` | 通用（`status_hero` 的正则只认第二阶段看板的句式，其他页走 `generic_hero`） |
| 名词卡 | 先认识几个名字 | `<details>` 标题“名词解释”，两列表 | `term_cards` | 通用 |
| 案例卡 | 几个情形各一句结论 | 连续几行 `X：一句话结论` 各跟正文 | `case_cards` | 通用 |
| 读法 | 图表之后告诉 Owner 怎么读 | `- **读这张图**：…` | `points` | 通用 |
| 折叠明细 | 一节只展开一张表 | `<details><summary>明细表</summary>…</details>` | `convert_details` | 通用 |
| 例框“输入 → 结果” | 规则落到钱上 | 步骤行末尾 `例（…）：a · b → 结果` | `_ex_visual` | 通用；排名、投票、金额拆分、两档比较四种会画成小图 |
| p = Φ(t) 曲线 | 把握换算 | 算式段含 Φ | `_phi_svg` | 专用 |

## 预测表评论轮次里学到的写法规则

- **先说这一步是干嘛的，再说规则。** 3.3–3.5 版卡片三次被评“看不出每张卡片要干嘛”：大字放的是规则或结论，读者要反推。改成“步骤名 + 决定什么”后过关。
- **窄卡片放不下中文。** 四张卡挤一行每列两百多像素，全是换行；3.6 版改成整行步骤表才不难受。
- **body 不能是段落。** 规则拆成标签（`a · b`），结果单独一格，例子写成“输入 → 结果”。
- **最重要的计算要画出来。** 把握 p 段被评“一眼看明白核心内容是怎么算出来的”：3.9 版改成三步算式表 + 两个名额的逐步数字 + 换算曲线。
- **数字跟着数据变，页面同时变。** 执行示例重算（3.22）时，图、算式表、步骤例框、读法里的数字一起改，否则页面自相矛盾。

## 合同类文档（预注册）怎么用这些模式

预注册是合同：**条款文字一字不改**，讲故事只能靠结构。

| 预注册的内容 | 用哪个模式 | md 怎么改写（条款不动） |
| --- | --- | --- |
| 每月四步 | 步骤表 | 四步表改成 `1. **选人**：**决定买哪 3 只**。看：…｜规则：…｜结果：…`；完整规则原文放折叠“规则全文” |
| 从数据里定的数字 | 计分条 + 表 | 表加“计不计”列的短标签；计分条显示“计 3 / 预算 3” |
| 设计评审的预测表、合成行情 | 结论图 | 直接用预测表的同一张图（原样进入，不另画） |
| 事前预判 | 结论图 | 四条判据各自的事先通过机会画成横条，合计约三成 |
| 判据 | 判据卡 | 每条判据一张卡：编号 + 门槛大字 + 一句话 + 来历 |
| 已看信息、数据陷阱 | 表 + 结论列 | 加“结论”列，取自原文的处理办法（只作一致性检查、执行成本、每次报告声明） |
| 疼痛表 | 列角色 | 表头“事先认下的代价”“超出就要查”触发代价色和 ⚠ |
| 冻结前待办 | 计分条 | “状态”列：已完成 / 待做 / 等数据 |
| 长格子 | 拆分 | 格子保留短语，长理由移到表下的读法或折叠，原文一字不丢 |

## 发布门的补充

- `scripts/owner_pages/audit.py` 从 `build.py` 的页面清单读页面，不再写死；新页面自动受查。
- 新页面的 lint WARN 数和 `audit.py` 的焦点缺口，不能比预测表多；多的逐条改或在发布说明里逐条解释。
- 每节问一遍：**证据视觉是哪个？** 没有的节要写明为什么不需要（例如只有一条规则）。
