## 核心：每个元素都是讲故事的人

Owner 十几轮评论反复说的是同一件事：**页面不是把内容排整齐，而是讲一个故事。** 落到每一层：

| 层 | 要回答的问题 | 合格的样子 | 不合格的样子 |
| --- | --- | --- | --- |
| 整页 | 只读标题和记忆句，能不能连成一个故事 | 预测表 §0 → §10：怎么执行 → 预计赚多少 → 为什么能赚 → 防守放哪 → 代价 → 定了什么 → 接下来 | 条款按编号堆叠，标题是“候选池”“对照”这类名词 |
| 一节 | 这一节的结论是什么、几秒内从哪看到 | 记忆句带数字 → 一个证据视觉（图、步骤表、计分条）→ 明细折叠 → 读法 ≤ 3 条 | 记忆句之后连着三四张表，没有图、没有读法 |
| 一个元素 | 看这里先看什么、为什么、和前后怎么接 | 步骤表：大字步骤名 + 蓝字“决定什么” + 标签化的看/判/得 + 例子“输入 → 结果” | 有边框、有加粗、但全是段落（“加粗 + 纯文本不合格”） |
| 一个格子 | 这一格是不是决定结论的那一格 | 整张表只框一两格；数字按方向上色 | 整列上色、长句塞满格子 |

**判断标准只有一个：Owner 不读正文，只看视觉重点，能不能讲出这一节的结论。** 讲不出来，就还没做完——不管 lint 有没有报错。

## 一节的标准骨架（预测表每节都是这个顺序）

1. `## 问题：结论`，结论里有方向和数字。
2. `> **记忆句**`：一句话，带决定结论的一两个数字。
3. **证据视觉**（必须有一个，按内容选，见下一节）。
4. `<details>` 明细表：带“结论 / 判 / 状态”列，短标签。
5. 读法：`- **加粗短语**：解释`，最多 3 条；第一条通常是“读这张图”。

预测表 11 节里 9 节有证据视觉；预注册初稿第 2 版 10 节里 0 节有（2026-11-23 自查）。

| 结论图 | 一节最重要的证据先给图 | `![图的标题就是结论](../assets/...png)`，脚本在 `scripts/preflight/charts_*.py` | figure | 通用 |
| 步骤表 | “每一步干嘛”一眼看出 | `1. **步骤名**：**决定什么**。看：a · b｜规则：c · **d**｜结果：e。例（月份）：输入 → 结果。` | `flow_steps` + `spec_grid` | 通用：任何 3–5 步流程 |

| 行内条 | 同列数字比大小 | 数字列 + 同量纲 | `.ib` | 通用 |

| 名词卡 | 先认识几个名字 | `<details>` 标题“名词解释”，两列表 | `term_cards` | 通用 |

| 读法 | 图表之后告诉 Owner 怎么读 | `- **读这张图**：…` | `points` | 通用 |
| 折叠明细 | 一节只展开一张表 | `<details><summary>明细表</summary>…</details>` | `convert_details` | 通用 |

## 预测表评论轮次里学到的写法规则

- **先说这一步是干嘛的，再说规则。** 3.3–3.5 版卡片三次被评“看不出每张卡片要干嘛”：大字放的是规则或结论，读者要反推。改成“步骤名 + 决定什么”后过关。
- **窄卡片放不下中文。** 四张卡挤一行每列两百多像素，全是换行；3.6 版改成整行步骤表才不难受。
- **body 不能是段落。** 规则拆成标签（`a · b`），结果单独一格，例子写成“输入 → 结果”。
- **最重要的计算要画出来。** 把握 p 段被评“一眼看明白核心内容是怎么算出来的”：3.9 版改成三步算式表 + 两个名额的逐步数字 + 换算曲线。
- **数字跟着数据变，页面同时变。** 执行示例重算（3.22）时，图、算式表、步骤例框、读法里的数字一起改，否则页面自相矛盾。

## 合同类文档（预注册）怎么用这些模式

预注册是合同：**条款文字一字不改**，讲故事只能靠结构。

| 预注册的内容 | 用哪个模式 | md 怎么改写（条款不动） |
| --- | --- | --- |
| 每月四步 | 步骤表 | 四步表改成 `1. **选人**：**决定买哪 3 只**。看：…｜规则：…｜结果：…`；完整规则原文放折叠“规则全文” |
| 从数据里定的数字 | 计分条 + 表 | 表加“计不计”列的短标签；计分条显示“计 3 / 预算 3” |
| 设计评审的预测表、合成行情 | 结论图 | 直接用预测表的同一张图（原样进入，不另画） |
| 事前预判 | 结论图 | 四条判据各自的事先通过机会画成横条，合计约三成 |
| 判据 | 情形卡 | 判据表加“门槛”短语列并标卡片：编号 + 门槛大字 + 判据原文 + 来历 |
| 已看信息、数据陷阱 | 情形卡 | 已看信息加“结论”列（取自原文的处理办法）并标 `<!-- 页面：卡片 -->`；陷阱表自动成卡 |
| 疼痛表 | 列角色 | 表头“事先认下的代价”“超出就要查”触发代价色和 ⚠ |
| 冻结前待办 | 情形卡 | 加“状态”列（已完成 / 待做 / 等数据）并标卡片，状态按颜色做大字 |
| 长格子 | 拆分 | 格子保留短语，长理由移到表下的读法或折叠，原文一字不丢 |

## 发布门的补充

- `scripts/owner_pages/audit.py` 从 `build.py` 的页面清单读页面，不再写死；新页面自动受查。
- 新页面的 lint WARN 数和 `audit.py` 的焦点缺口，不能比预测表多；多的逐条改或在发布说明里逐条解释。
- 每节问一遍：**证据视觉是哪个？** 没有的节要写明为什么不需要（例如只有一条规则）。
- 合同条款格（规则原文）超长可以保留，在发布说明里逐条列出；其余长格按上表改写。

## 第 2 版：讲故事层（2026-11-24，v6 预注册初稿第 2.2 版）

**根因**：第 1 版的焦点是生成器从条款原文里“猜”出来的（加粗、数字、结论列）。条款句子是中性的，猜出来的是样式，不是观点；元素之间也没有接力。Owner 的判断：“每个原子元素没有直接的讲故事效果，原子之间没有连贯、闭环、往前推的故事线。”

**修法**：焦点由作者写进 md，生成器只负责把它放到最显眼的位置；条款原文一字不改，留在下面。

| 标记（写在 md 里） | 页面上变成 | 规则 |
| --- | --- | --- |
| `<!-- 问：……｜短：两三个字｜状态：已定 / 待你定 / 待补 -->`，紧跟 `##` 标题 | 标题下一行“这一节回答：……”；页首的故事主线（每节一个节点，带状态色） | 每个 `##` 节都要有 |
| `<!-- 看点：一句话｜框：格子里的字 / 另一个 -->`，紧贴在表、卡片组、图、定义格、步骤流的上方 | 蓝底“看点”条；“框”里的字所在的格子、卡片标题、步骤短语被框出来 | 看点只能说源文档里有的结论；框必须找得到，找不到构建时报错 |
| `<!-- 接力：…… -->`，节的最后一行 | 虚线“所以 → 下一节”链接 | 说清楚这一节的结论为什么把读者带到下一节 |
| `<!-- 页面：定义 -->`，在“**名词**：规则……”列表上方 | 三栏定义格：名词 / 第一句规则（其余句子灰字）/ 出处小标签 | 18 字以内的引用括号移到出处标签；长括号留在句子里 |
| `<!-- 页面：参考 -->`，在查阅用的表上方 | 表标 `data-lint="ref"` | 只给查阅表用；它的看点仍然要写 |

**写看点的规矩**（来自冷读测试的问题）：

- 看点说几个数，就框几个；只框一个而看点说三组，读者会以为另外两组不重要。
- 看点要说图上真正画的东西；图里框不了，就点名“看哪根柱、哪个数字”。
- 和标题、一句话答案用同一个数（例：标题说“4 项”，看点不能说“六项”而不解释）。
- 同一组卡片按看点分组，组的看点就是组标题；卡片标题用“看过什么”的加粗短语，结论放大字，不重复。

**发布门加一道**：`python scripts/owner_pages/story_check.py <page.html> --digest 连读稿.md`，0 个 ERROR 才发布。检查：每节有问（Q）、有接力（NEXT，最后一节除外）、每个证据元素有看点（LOOK）、框都找到了（BOX）、同组卡片标题不重复（DUP）、折叠外没有超过 120 字的段落（WALL）。`--digest` 输出只含标题、问、答、看点、接力的连读稿：两分钟能读成一个完整故事才算过。

**冷读测试**：每节截图（折叠全部展开），交给没看过源文档的独立 agent，只回答四件事：这一节的结论、视线先落哪、哪个元素读不出要点或看点与框对不上、接力是否成立。它列出的问题清零或逐条说明后再发布。v6 预注册 2.2 版第一轮冷读列出 10 条，主要是看点与框不一致、图里的数字没被点名，全部按上面的规矩改了。

| 指标（v6 预注册） | 2.1 版 | 2.2 版 |
| --- | --- | --- |
| 有“这一节回答”的节 | 0 / 10 | 11 / 11 |
| 有看点的证据元素 | 0 | 43 |
| 有接力的节 | 0 | 10 / 10（最后一节回到页首） |
| lint ERROR / WARN | 0 / 4 | 0 / 6（5 个条款格或基金清单格、1 条条款列表项） |

## 第 3 版：形式跟着内容走（2026-11-24，Owner 对 2.2 版的反馈：接受度约四成）

**根因**：第 2 版在条款原文上面又加了一层看点（全页 43 条），默认视图的字数从 13,056 没有降下来，焦点仍然是文字。检查只核对“有没有看点”，没有核对“第一眼要读多少字”。Owner 指出预测表做对的四件事：

1. **展开前的信息熵集中**：看得见的每个元素都是高信息量的数字或结论，没有铺垫句。
2. **同一节的几张表用不同形式**：流程用步骤格，配仓用堆叠条，计算用流水线加大数字。
3. **折叠里的明细表素净**：展开后是干净的表，没有多余的颜色、框和看点条。
4. **表上方的小视觉**：对比进度条、副标题高亮。

**修法**：每节默认视图 = 标题 + 一句话答案 + 一个按内容选的视觉 + 折叠里的条款原文 + 一行接力。看点条全部撤掉；组件在 `scripts/owner_pages/components.py`，md 里用 `<!-- 组件：名称｜标题 -->` 加一张小数据表：

| 组件 | 内容的结构 | 用在 |
| --- | --- | --- |
| 分拣 | 一组条目按结论归成几类 | §4 已经看过的信息 |
| 闸门 | 几道必须全过的门槛 + 事先机会 | §5 判据 |
| 构成 | 几个组合的成分比例 | §5 基准 |
| 计数 | 一组东西按类别计数（预测表 04 节的对比条） | §1 常数来历、§6 代价来源、§8 陷阱 |
| 路线 | 有先后、有“现在在哪一步” | §7 上线路径、§9 冻结流程 |
| 退路 | 条件不满足就往下一档退 | §2 买哪只基金 |
| 载体 | 一组名字按类型分行（芯片） | 附表 A、§5 结果怎么用、§7 影子与暂停线 |
| 代价 | 按来源分组，每条有一个可比的代价和一条警戒线 | §6 疼痛表（组名做左侧色条，代价大字，警戒线红字） |
| 风险 | 有先后顺序的几条风险，每条有盯的地方 | §3 红队（第一名红框） |

`<!-- 框：格子文字 -->` 只框可见表里唯一决定性的格子；折叠里的明细表不加看点、不加框。

**发布门加两道**（`story_check.py`）：DENSE，每节不展开时 ≤ 700 字；FOCUS，每节在折叠外有一个视觉。`audit.py` 不再要求折叠里的明细表上色。

| 指标（v6 预注册） | 2.2 版 | 2.2 版改版后 | 预测表（参照） |
| --- | --- | --- | --- |
| 不展开可见字数 | 13,056 | 约 5,150 | 5,899 |
| 单节最多 | 2,889（附表 A） | ≤ 700 | 1,035 |
| 看点条 | 43 | 0 | 0 |

## 第 4 版：每一块都按内容选形式（2026-11-25，v6 预注册冻结前后约 45 条评论）

**根因**：第 3 版把“折叠里的明细表素净”做成了“折叠里平铺表”，又把粗体加纯文本当成重点。Owner 的标准是每一块展开后都要 3 秒看出重点，折叠里也一样；“大部分是 Bold plaintext”被直接点名。

**修法**：
- **冻结文档**：预注册冻结后 md 一字不动，所有页面改动做在 `scripts/owner_pages/forms.py`。它按表头签名（或定义名词、折叠标题）认出一块内容，换成对应形式，认不出就原样保留。冻结后页面加横幅、标题改“已冻结”（`build.py` 的 `FROZEN`）。
- **形式目录**：见技能 `.pi/skills/owner-page-uiux/SKILL.md` 第 3.8 节，共 20 种内容结构各自对应一种形式，例如：
  - 规则四步 → 步骤行；
  - 算式 → 三步算式条；
  - 两条规则 → 对照；
  - 常数来历 → 分组；
  - 判据 → 和图对应的卡片；
  - 退路 → 逐级下沉的台阶；
  - 时间轴 → 带编号和每步判定条件；
  - 代价 → 数字放大加刻度条；
  - 逐年数据 → 月格加仓位条；
  - 净值 → 条形加对基准的差。
- **写法规则**：
  - 粗体只给数字和决定；
  - 决定编号（D39-1）改成说人话（“你 11-17 定的回撤底线”），编号缩成灰字；
  - 第一次出现的术语（K2A）在页面上补解释，并注明出处；
  - 只出现一次的重复值（口径、截止日）提到表上方。
- **生成器的坑**：
  - 表头字号比内容行小、列宽又用 em 时，表头会和内容错位；
  - `story.py` 给 `ol` 加的 `flow`、`steps-n` 要用更高优先级覆盖；
  - `.num` 底色在大数字处要去掉；
  - `el.py` 截图写进 `shots/`（已加入 `.gitignore`）。
- **评论处理**：每次把所有等回复的评论一起改完、一起发布，再逐条回复；同一处被评第二次，先换形式，不在原形式上加装饰。
