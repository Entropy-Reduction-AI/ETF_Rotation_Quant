## 交给 Orchestrator 的字面歧义

1. **F 的名字。** 过关表里的 P2 是「上一版 + C2」。上一版是 S0，所以 F 的内容是 S0+C2，不是 S0+C1+C2。臂名仍叫 P2，开关在账本 `enable_c1=false`、`enable_c2=true`。
2. **过关表的 `ann_excess_*` 是该臂自己的 A，不是相对上一版的差。** 差在 pass 列和 `tradable_d_*` 里。S0 的 pass 以及其余 pass 列、`tradable_d_*` 留空。
3. **稳健性行的 `base_arm` 是 F 的部件上一版（S0），不是对照的比较对象。** 比较对象是 `final_arm`（P2）。账本的 `arm` 列是对照名（如 `lookback-10-40-90-180`），避免盖掉 P2 那一行。
4. **「最好」的容器。** v5 正文没有重定义。这里沿用 v3/v4：该容器自己在行情里的累计收益，高的在前，相同则名字较小的在前；先排好再去掉前 1、2、3 名。
5. **结构对照保留 F 的 C2。** 只改每个回看期里的第 3 步。C1 本次没开。邻近回看期只换 v5 配权的四个 L；`run_arm` 仍把原来的 spec 交给溢价的滚动前推，不按新的 L 重选 (W, θ)。
6. **「很敏感则降一级」没有数值门槛。** 这次只把差值写进 `robustness.csv`，不降级，也不因此改 F。
7. **`max_drawdown_2006`** 用 2006-01-01 → 2015-12-31 的日净值，和 §6.3 对最大回撤的区间写法相同。它不是入围检验。
