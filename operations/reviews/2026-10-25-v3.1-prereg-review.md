- 冻结 v3 §3.1：**U-指数**成员「从**指数发布日**起计入（不用发布前倒推数据）」。

## 增量可执行性（§4.5 · 单只 10% 离场）

**已足够清晰的部分**

| 要素 | v3.1 规定 | 与 v3 关系 |
| --- | --- | --- |
| 阈值 | 收盘价 \< 持有期最高收盘价 × 90%（回撤 10%） | 固定；非 §7.1 候选 |
| 最高价 | 每次**调仓执行后**重置；与**收益所用序列**相同 | 可执行 |
| 触发后动作 | **下一交易日收盘**全部卖出 → 现金；成本 §4.3 | 信号日 vs 成交日清楚 |
| 再入场 | **下一个调仓决策日**重新排名；执行后重新记最高价 | 可执行 |
| 参数 | 10% 固定；§7.2 另报 8%/12%/15% 只报告 | 与 D10 一致 |
| 范围 | 每个 **(N, 频率)** 子组合 | 见 B2 |

**边界（可默认、不阻塞）**

- 同日多只触发：各容器独立判断、独立次日卖出；未写并列顺序，按容器代码稳定序即可。
- 调仓日已低于 10%：执行调仓后重置 peak，按新持有期重新跟踪。
- 再入场前不再单独跟踪已清仓名（直至下一调仓决策日）。

**阻塞项 B2 · §4.5「子组合独立」与冻结 v3 §4.4 A 臂「六组合成后一次成交」**

- v3 §4.4：A 臂对六个 (N, 频率) 先各自算权重，再对权重**算术平均**，得到**单一**目标持仓并成交（一套持仓、一套净值）。
- v3.1 §4.5：每个 (N, 频率) 子组合**独立**执行离场（独立 peak、独立卖出）。
- Orchestrator E2（`v6.py`）：六个 `run(..., stop=0.10)` 的日收益序列再 `mean(axis=1)`——是**六条净值路径平均**，不是「合成权重 + 一套止损」。
- 两套语义在 2015 年回撤、现金比例上可 materially 不同；D10 证据链写的是 E2，与「仅合成权重」引擎不对齐。

**需在预注册中由 Owner 落字**：

- A 臂（及写「同 A」的 S1/S2）正式引擎应采用哪一种：
  - **(i)** 合成权重后的**单一**组合上做单 peak / 10% 离场；或
  - **(ii)** 六路子组合各自持仓与离场，组合收益 = 六路日收益算术平均（权重不再合成后单路径成交）。

未决前，Dev **不能**在无歧义前提下对接「正式引擎 A 臂」与「Orchestrator E2 26.0%」验收。

**跟进项 F2（不单独构成 return，但随 B2 一起解决）**

- §4.5 未写是否适用于 **B 臂**（每年单选一组 (N, 频率)）——建议显式写「B 臂仅对当年选中那一组应用 §4.5」；默认可推断。
- **U-可交易 + QDII**：§4.1 对 QDII 用净值算 R/s；§4.5「与收益序列相同」在 S1（场内价）与 U-可交易 主序列上需在实现说明中钉死，宜在 v3.1 或 L2 签收写一句。
- **§5 溢价**：离场发生在非决策日时，仅 §4.3 成本；决策日仍 §4→§5。与 v3 顺序兼容，建议在 Dev 设计里写死「止损成交日不走 §5.2 状态机」。
