## 4. §6.2 过关规则与 §6.3 判据 ⑥ · 打分卡（v4-R3）可算性

### 4.1 判据 ⑥（顺应市场）

- **可算**：与 `classify_months` / `label_state`、`state_frame`、`state_table` 一致——日超额按月求和再按状态汇总（`excess_pp`，1 位小数）；通过条件为 **牛市、反弹** 的 `excess_pp ≥ 0**（严格还是 ≥0 与「不能为负」一致）。
- **输入**：最终版（或任意 arm）的**日收益序列** + BM-主 日收益 + 六路合成现金权重（或 scorecard 约定的 `held_cash`）；**不能**只用 v4-R3 的 REFERENCE 常数（那是 E2 P1 快照）。
- **注意**：看板整数 = 对 `excess_pp` 四舍五入（v4-R3 §C）；判据应用 **1 位小数或完整求和**，预注册应写死，避免 0.6pp 展示为 +1 却判失败。

### 4.2 §6.2 候选过关（相对 B0）

| 规则 | 能否从现有 scorecard 直接输出 |
| --- | --- |
| ① 两段年化超额均 &gt; B0 | **否**。缺：日历段边界、策略/B0/BM 三序列的子样本年化超额定义及差分。 |
| ② 指定状态累计超额 &gt; B0 | **部分**。状态分解逻辑可复用 `state_table`，但需 **候选与 B0 各跑一条序列** 并对同一状态做差；scorecard 无 `pass_candidate()` 或 B0 列。 |
| ③ 熊市累计超额 ≥ B0 − 10pp | **部分**。同上；「累计超额」与 ② 应用同一「日超额按月相加」口径（正文已写与打分卡同法——好），但 **10pp 比较对象**（B0 熊市格 vs 候选）须写公式。 |

**结论**：v4-R3 交付的是 **⑥ 与任意起点报告的算法基线**，不是 §6.2 过关机。须在预注册 §7 或单独 `results/v4/` 报告 schema 中定义字段（例如 `subperiod_excess_vs_b0`、`state_excess_delta_pp`），或扩展 scorecard 模块并在此引用——对应 **MF-3**。

### 4.3 判据 ① 与 D12-2

- v4-R3 scorecard 实现的是 **D12-2 任意起点**（1/2/3/5 年，`anystart.py` 年化）。
- v3 §6 **①** 仍是 36/60 **自然月**窗口 + 252/n 年化 + 中位/比例门槛。
- §6.3 写「沿用 ①–⑤」且「任意起点为主要报告方式」——**未**说 ① 被 D12-2 替换 → **MF-5**。

## 5. 预算与计数公式

### 5.1 §9.2 ledger 上限 60

- 估算：2 池 ×（B0 + T1 + T2 + T3 + T4 + 最终版 = **6** + 稳健性 **9** = **15**）= **30** → 低于 60，**算术一致**。
- **缺口**：稳健性 9 是否每条都写 ledger、是否与主配置共用 `arm` 命名、失败重跑是否占行——预注册未写，建议比照 v3 §9.6「每配置一行」补一句。

### 5.2 §6.3 ⑤ 尝试次数

- 正文：`len(v3 ledger 中 v3/v3.1 行) + len(v4 ledger 中 v4 行) + 28 + 35`，排除 `C1-shadow`；IC 不计入（D14-7）。
- **风险**：两文件「配置行数」是否含 segment 重复、v4 是否只计 `results/v4/trial-ledger.csv` 新行——**MF-4**。
- 与 addendum A3 关系：35 与 28 已对齐 addendum；v4 将 v3 ledger 行继续计入（不重置）——合理，但需防 v4-R5 **重登记** v3 配置导致 double count。
