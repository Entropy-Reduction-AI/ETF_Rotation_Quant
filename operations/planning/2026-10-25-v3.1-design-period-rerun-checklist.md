## 2. 命令形状

仓库根目录、合入之后的代码：

```bash
export ETF_V3_RUNNER=dev
.venv/bin/python -m src.v3.engine \
  --arm ARM \
  --pool POOL \
  --end 2015-12-31 \
  --history-mode MODE \
  --exit-drawdown DD
```

- `ARM` 是 `A`、`B`、`S1`、`S2` 之一。
- `POOL` 是 `index` 或 `tradable`。
- `MODE` 是 `official`（主口径）或 `publish_date`（只报告的对照）。
- `DD` 主规则是 `0.10`。稳健性入口只接受 `0.08`、`0.12`、`0.15`。其他数值会直接拒绝。
- 不传 `--end` 时，结束日来自 `config/v3/arms.toml` 的 `design_end`。复跑仍要写上 `--end 2015-12-31`，避免以后有人改了配置却沿用旧命令。
- 标准输出一行，形如 `arm=... pool=... <起>→<止> n=... cagr=<小数> max_drawdown=<小数>`。`<止>` 必须 ≤ 2015-12-31。晚于这一天的输出整行作废，不抄进报告。
- 不加 `--debug` 时，同一 `arm` + `params` + `segment` 会在 `results/v3/trial-ledger.csv` 追加一行；完全相同的配置已有一行时不再追加。去重不看 `git_sha`。同一配置在新提交上重跑，不会自动记下新的 SHA，也不要删旧行来腾位置。
- `--debug` 不写 ledger。给 Owner 的正式数字不要只来自 debug 输出。debug 可以用来确认结束日，不能代替正式行。
- `--n` 与 `--freq` 必须同时给，而且只跑候选集里的一组：`N` 为 3、5、8，`freq` 为 `week` 或 `month`。一旦给了这组参数，ledger 的 `arm` 列写成 `group`，返回的是这一路，不是六路平均，也不是 B 臂的滚动选择。要记 A、B、S1、S2 时，不要带 `--n` / `--freq`。

主规则的 10% 已经包含在不改 `--exit-drawdown` 的正式命令里。8% / 12% / 15% 是额外配置，每跑一条非 debug 就占预算一行。

不传 `--premium-window` 与 `--premium-theta` 时，按 v3.1 已写的路径处理（未传入则在 A 臂上逐年选择；指数池不接溢价，这是 #39 工作记录里的实现说明，签收时由 Reviewer 核对）。两个溢价参数要同时给，候选只有 W ∈ {120, 250}、θ ∈ {0.10, 0.15}。只给一个会退出，不会跑完。溢价对照里「只保留 §5.3 上限、不跑状态机」在这个命令行上没有开关。没有开关就不要发明一个。

## 4. 预算里已点名、执行前要另勾选的配置

这些配置出现在 v3 §9.6 或 v3.1 §4.5 / §6 的预算说明里。勾选才会跑。不勾选就不要跑。每一条非 debug 运行按冻结条文计入 60。

### 4.1 六个 (N, 频率) 子组合

两个池都可以列。U-指数、官方口径、10% 的六条是：

```bash
.venv/bin/python -m src.v3.engine --arm A --pool index --end 2015-12-31 \
  --history-mode official --exit-drawdown 0.10 --n N --freq FREQ
```

`N` / `FREQ` 六组：`3 week`、`3 month`、`5 week`、`5 month`、`8 week`、`8 month`。ledger 的臂名是 `group`。U-可交易把 `--pool` 换成 `tradable`，另计行。不要用 `--arm B` 加 `--n` 来冒充 B 臂。

### 4.2 离场稳健性

只在勾选后，对 A / U-指数 / 官方口径追加。10% 已经在第 3 节第 1 条，不要再跑一条相同的。

```bash
.venv/bin/python -m src.v3.engine --arm A --pool index --end 2015-12-31 \
  --history-mode official --exit-drawdown 0.08
```

把 `0.08` 换成 `0.12` 和 `0.15` 各一条。预注册没有要求 U-可交易默认同跑这三档。未勾选不加跑。跑完只报告，不挑最好的一档，不改主规则。

### 4.3 成本加倍

命令行上有 `--cost-multiplier`。勾选后：

```bash
.venv/bin/python -m src.v3.engine --arm A --pool index --end 2015-12-31 \
  --history-mode official --exit-drawdown 0.10 --cost-multiplier 2
```

U-可交易是否同跑，按预算勾选，不默认。

### 4.4 其余 §7.2 情形：没有命令行

决策日再晚一个交易日、去掉美股主题、去掉商品、去掉累计收益最好的 1 / 2 / 3 只，实现在 `src/v3/eval/robustness.py` 的 `robustness_books`。该函数没有独立命令行，而且现有实现直接调用执行函数，不写 ledger。L4 工作记录写过这些函数不写尝试记录；v3 §9.6 又把稳健性 7 行算进预算。这个差是未决事项 O4，不在本清单里用一次新的运行方式把它抹平。没有命令行的情形，在入口被签收之前不要手写一段脚本当场跑。

### 4.5 溢价的四组显式参数

只属于 U-可交易。勾选后才跑，每组一行：

```bash
.venv/bin/python -m src.v3.engine --arm A --pool tradable --end 2015-12-31 \
  --history-mode official --exit-drawdown 0.10 \
  --premium-window W --premium-theta THETA
```

四组：`(120, 0.10)`、`(120, 0.15)`、`(250, 0.10)`、`(250, 0.15)`。这四组是报告用的显式参数，不是让 B 臂或主规则改去选其中最好的全期结果。逐年选择由第 3 节表格第 6 行承担：A / U-可交易 / 官方口径 / 10%，不带这两个溢价参数。

「只有 §5.3 上限」的对照没有命令行开关。不发明开关，这一行留在预算表里标成「无入口」。

v3 §5.5 的 2021–2026 溢价机制对照会碰到 2016 年以后的区间。本复跑不跑那段组合收益。

### 4.6 共同口径对照探索 E2

不设正式命令。诊断成本是 0.1%×换手，容器是诊断日志里的 18 个序列，黄金用的是 GLD。`--cost-multiplier` 不能把分资产费率换成那一种成本，也没有「只用这 18 个容器」的开关。在这样的入口出现并被签收之前，不要跑一条近似命令，再把它的年化写成「与 26.0% 的共同口径差」。探索数字保持在诊断日志里。
